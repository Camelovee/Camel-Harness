# 工具安全设计

工具执行链统一处理参数、授权、超时和结果保存。安全规则以绑定的工作区、会话和本次权限模式为输入，模型给出的工具名、参数及外部结果都需要经过这些边界。

## 1. 工具执行链

`Tool` 声明名称、JSON Schema、风险、能力和执行方法；`ToolProvider` 提供工具集合，`ToolRegistry` 负责注册及规范工具定义。默认集合只有 `read_file`、`write_file`、`edit_file`、`run_shell`，其他能力由入口注入。

Agent 仅接收 ToolExecutor，通过其 `llm_definitions()` 获取工具定义，执行也由同一实例负责。查询实时委托给执行器持有的 ToolRegistry，组装期间追加的委派工具同样可见，避免分别注入两份注册表产生不一致。

```text
完整模型响应落盘
  → 解析已完成的工具调用
  → 注册表查找
  → 固定工作目录、深拷贝参数并做 JSON Schema 校验
  → PermissionService / WebApproval
  → 带超时执行工具
  → 结果归档或内联
  → Agent 保存完整 ToolResultMessage
```

当前 Turn 的工具按顺序执行。未知工具、参数错误、审批拒绝和一般执行错误被归一化为错误结果；取消继续传播。工具结果归档失败单独抛出 `ToolResultStorageError`，终止 Run，避免把“命令执行后保存失败”伪装成“命令没有执行”。

`tool_execution_start` 表示开始处理，可能尚未审批；`tool_execution_end` 是工具归一化结果，后续保存仍可能失败。消息保存成功由 `message_end` 确认。

## 2. 权限与浏览器审批

| 本次模式 | 只读 | 工作区编辑 | Shell / MCP | 记忆保存、删除 |
| --- | --- | --- | --- | --- |
| `default` | 允许 | 询问 | 询问 | 询问 |
| `accept_edits` | 允许 | 允许 | 询问 | 询问 |
| `plan` | 允许 | 拒绝 | 拒绝 | 拒绝 |
| `yolo` | 允许 | 允许 | 允许 | 询问 |

记忆修改规则先于通用 YOLO 判断。工具内部还可以拒绝危险操作，权限允许不会绕过文件路径校验或 Shell 危险命令规则。

`WebApproval` 为每次请求保存目标参数和一个等待结果的 Future。浏览器通过审批接口批准或拒绝；默认 300 秒无响应返回拒绝，完成、超时或取消时移除待办。没有审批处理器的询问请求不能执行。

审批队列当前只在后端进程内存中，重启后不能恢复。审批授权的是该次调用参数，不是给同类未来调用永久授权。执行器在等待审批前固定规范工作目录并深拷贝参数，后续修改原始参数不会改变批准后的操作。

工具可通过只读 `approval_context()` 提供运行时生成的展示信息；默认返回空映射。Shell 的 `execution_context` 包含实际工作目录与完整命令，审批事件和待办查询均传递该上下文，WebUI 直接展示，不省略多行或长命令。Windows 的 UTF-8 初始化前缀也包含在完整命令中；审批与执行复用同一命令构造函数。这些字段不接受模型参数注入。

## 3. 文件工具边界

普通读写将路径规范化后检查是否位于工作区内，拒绝 `..` 或符号链接解析导致的工作区逃逸。工作区内的绝对路径同样接受这一归属校验。

`read_file` 对工作区外有一个受控例外：当前 Session 原始分支已经保存的 `content_ref` 工具结果。必须同时满足：

1. 路径为不含 `..` 的绝对路径，直接位于所属会话 `tool-results/`；
2. 目录、目标不是符号链接或 Windows 重解析点；
3. 路径在当前分支的完整工具结果中登记，且仍是有效文件。

只看到模型正文中的绝对路径、猜到同会话文件名或持有另一会话引用，都不能获得读取授权。该例外不扩大写入和编辑范围。

`write_file` 与 `edit_file` 禁止直接修改项目及用户记忆目录，包括规范路径别名。记忆只能通过专用审批工具维护。普通文件路径检查不是操作系统沙箱，也不承诺抵御恶意进程同时置换目录产生的所有竞态。

## 4. 修改与取消的一致性

`read_file` 只读取 UTF-8 文本，保留 `start_line/max_lines` 参数。默认 400 行、最多 2000 行；带行号正文还受 16 KiB UTF-8 字节上限约束，只返回完整行。正文和 metadata 同步提供实际 `start_line/end_line`、`total_lines` 和 `next_start_line`，未读完时明确给出续读参数。空文件明确提示；起始行越界报错；单行超限时不输出半行、不自动执行 Shell，而是说明无法完整展示该行。当前仍先读取整个文件，不承诺降低大文件的峰值内存。

`write_file` 仅接收 `path/content`，创建或完整覆盖目标，自动创建父目录。覆盖前应了解已有内容，局部修改优先使用 `edit_file`；完整正文不得省略。原有 `expected_revision`、文件哈希与 `file_revision` 已移除，不维护隐式读取版本缓存。成功结果报告路径及 UTF-8 字节数。

`edit_file` 接收 `path/edits`，每项为 `old_text/new_text`。同一路径修改锁内只读取一次原始快照，每项必须唯一匹配原文，所有区域不得重复、重叠或嵌套；任一校验失败都不写入，报告“未执行”。不匹配前一项替换后才出现的内容。匹配时只统一换行表示，不做引号、空白或 Unicode 模糊匹配。

编辑保留 UTF-8 BOM 和未修改区域原文；替换内容使用原文首个换行风格，无换行时使用 LF。全部验证后一次原子写入，返回片段数量及 unified diff，大结果沿用归档。没有实际变化时报告未执行。

相同规范路径的修改使用进程内队列串行化，防止工具调用的读改写交错。但完整覆盖不检查版本，不识别模型是否基于旧内容操作，也不能防止另一个 Agent 或外部编辑器的修改被覆盖。

文件修改采用同目录临时文件：写完整 UTF-8 内容、flush/fsync、保留已有权限后原子替换。失败清理临时文件。普通文件工具没有与 JSONL 的跨文件事务，也不承诺掉电后的目录项持久化。

等待队列时取消不会执行修改；线程已经开始写入时，协程等待线程完成后才释放路径锁并传播取消。取消不等于撤销已写入内容。这里的队列是进程内机制，不是多个外部编辑器之间的互斥协议。没有提供跨进程版本校验、跨文件事务或独立工作区隔离。

## 5. Shell、MCP 与子 Agent

Shell 在工作区作为 cwd 启动命令，以危险命令模式做保守拒绝，并限制执行时间。Unix 使用独立进程组；Windows 使用 `cmd.exe`、UTF-8 输出与进程组，超时或取消通过进程树清理结束后代。

Shell 可以运行程序并访问宿主机能力，命令正则不是完整命令解释器；进程主动脱离进程树、绕过文件工具修改 Memory、访问网络等行为不在上述工作区检查保证内。

MCP 工具按外部风险走同一审批链。Server 的 cwd 强制设为工作区，但其进程权限没有被降级。连接上下文由 McpManager 的唯一任务管理，单个 Server 连接失败就地清理；当前不做自动重连或在途调用重放。

子 Agent 工具采用明确白名单：

- `explore` / `plan`：`read_file`、`load_skill`、`search_memory`、`read_memory`，使用 PLAN 权限；
- `general`：在上述集合上增加文件写入、编辑和 Shell，继承父任务权限模式；
- 所有子 Agent 都没有二次委派、Memory 修改或 MCP 工具；模型跟随父 Run，会话及结果引用独立。

子 Agent 是运行对象和会话隔离，不是独立 OS 安全边界。

## 6. 截断响应、工具副作用与结果归档

工具结果在现有 `metadata`（消息中为 `details`）携带 `execution_status`，不改变 JSONL 事件格式和 `is_error` 字段：

| 状态 | 含义 |
| --- | --- |
| `not_executed` | 明确在实际操作前拒绝，例如参数/审批拒绝、编辑匹配失败或重叠、Shell 启动失败 |
| `succeeded` | 工具报告正常完成 |
| `failed` | 已知执行失败，例如 Shell 非零退出、MCP 返回工具错误；不保证没有部分副作用 |
| `unknown` | 已进入操作但无法确认最终结果，例如超时、MCP 通信异常及可能产生副作用的执行异常 |

执行器统一补齐状态，工具可返回更准确的分类。Shell 自身超时和执行器超时都使用 `unknown`；本地取消 MCP 等待不证明远端已经停止或撤销。取消仍向上传播，不转换成普通错误结果；原有中断恢复仍提示先检查环境。

未知结果正文以“操作可能已经产生副作用，请先通过只读方式核验实际状态，再决定是否重试”开头，归档预览即使配置很小也完整保留该提示。状态经过事件、归档与会话重载保持一致；WebUI 显示“未执行／已完成／执行失败／结果未知”，旧日志没有字段时沿用原标签。默认提示要求模型先核验，不新增自动重试或强制暂停，也不能据此宣称程序已证明核验完成。

流缺少完整完成事件时不保存 assistant 消息，也不执行其增量工具参数。响应以 `length` 完成时，工具调用只补错误结果而不执行；Agent 最多允许一个重新规划 Turn，不能自动重放残缺调用。

普通超大结果归档完整文本并返回预览与结构化引用；Shell 输出分块处理，避免一次装入全部内存。归档失败时工具可能已经产生副作用，Agent 结束并闭合工具消息链，恢复时提示检查环境，不自动重试历史命令。

配置 API 不回传密钥，配置校验不回显输入原文；这些边界不等于工具正文已自动脱敏。任务及工具可接触的工作区内容仍由用户管理。
