# 上下文管理设计

本文描述当前 `ContextManager` 如何为每次模型请求准备动态系统提示与历史压缩计划。历史压缩算法见 [上下文压缩设计](上下文压缩设计.md)，持久化及历史树见 [会话系统设计](会话系统设计.md)。

## 1. 为什么单独管理上下文

会话负责保留完整历史，模型请求需要的是在预算内、适合继续任务的上下文。将两者分开后，资源检索和摘要生成可以失败而不改写会话，模型厂商适配也无需理解本地文件或 Session。

当前分工是：

| 组件 | 输入与输出 | 可执行的操作 |
| --- | --- | --- |
| Agent | 用户目标、本次模型、绑定会话 | 保存消息、读取快照、协调准备与提交 |
| ContextManager | 只读快照、查询文字、基础提示、工具定义 | 读取动态资源，返回 `PreparedContext` |
| CompactionEngine | 快照与估算开销 | 调用模型生成摘要，返回计划 |
| Session | 原快照与压缩计划 | 校验并提交，返回新的持久化快照 |

`PreparedContext` 只有系统提示和可选 `CompactionResult`；没有可直接写会话的存储句柄。Context 仅从 `session.events` 导入快照类型，Import Linter 禁止其依赖会话存储模块和运行状态。

## 2. 每个 Turn 的准备顺序

1. Agent 如有新用户消息，先将其完整保存；随后读取当前分支的 `ContextSnapshot`。
2. 获取当前工具注册表的规范 `ToolDefinition`，将这些定义和基础系统提示交给 ContextManager。
3. ContextManager 重新读取项目规则、发现 Skill 索引、检索相关 Memory，组装动态系统提示。
4. 根据历史、系统提示和工具定义的估算开销判断是否需要压缩。
5. Agent 提交有效压缩计划；仅在 Session 返回新快照后，才构造下一次 `LlmRequest`。

每次准备都从基础提示重新构建，避免上一轮注入的规则或记忆累积。steering 输入在 Turn 安全点保存为新用户消息，并成为后续资源检索的查询文字。

普通 `run(prompt)` 直接使用本次 prompt。`resume()` 从当前分支的原始完整消息中选择最近一条用户消息，避免把压缩摘要当作用户目标；没有用户文字时回退为“继续当前任务”。

## 3. 三类动态资源

### 项目规则

`ProjectRules` 只读取绑定工作区根目录的 `AGENTS.md`。文件缺失返回空内容；存在但读取失败则交由资源错误边界处理。注入上限默认 12,000 个字符，超出部分截断。

当前没有向上逐级搜索或对子目录规则自动叠加的逻辑。文档中“项目规则生效”指这一明确的读取范围，不表示实现了任意层级规则系统。

### Skills

来源依次为内置目录、`<workspace>/.camel/skills/`、`~/.camel/skills/`，同名优先级为内置 > 项目 > 用户。

- 发现阶段只读 `SKILL.md` frontmatter 的名称和描述。
- 任务需要时由模型调用 `load_skill` 读取正文。
- 正文引用的支持文件再通过 `load_skill` 的相对 `path` 参数读取，路径必须留在该 Skill 目录中。

Skill 正文和支持文件不会因发现索引而全部进入系统提示。发现阶段会跳过链接、格式不合规或无法读取的条目；显式加载错误作为工具结果返回。

### Memory

ContextManager 按当前查询调用 `MemoryStore.search(..., tolerant=True)`。默认最多选 5 条，总预算为估算 2,000 Token，包含标题、层级、版本、说明和正文。

每条优先注入完整正文；放不下时尝试仅放索引和 `read_memory` 提示；连提示也放不下则跳过。零匹配不注入全量目录。提示明确将记忆标为参考资料，不能覆盖用户目标、项目规则和权限。

关闭 `memory.enabled` 后，入口不注入 Memory 对象及其工具；ContextManager 也检查关闭标记。该选项不删除已经保存的记忆。检索、审批和版本规则见 [记忆系统设计](记忆系统设计.md)。

## 4. 上下文预算

估算采用 UTF-8 字节数除以 3 向上取整，不是厂商精确 tokenizer。开销分为：

- 模型可见的历史消息投影；
- 本次系统提示，包括动态规则、Skill 索引与 Memory；
- 工具名称、描述和 JSON Schema。

历史估算和摘要输入过滤 assistant 的 reasoning 展示块、模型审计字段和工具结果 details。工具正文与参数仍计入模型可见历史；自动 Memory 预算是总系统开销的一部分，不是额外免费窗口。

配置中的 `compaction.context_window_tokens` 需要与实际模型匹配。切换模型不会自动查询或推导上下文窗口，Provider 报告超限时仍可能进入一次有界强制压缩恢复。

## 5. 错误、取消与配置生效

| 失败阶段 | 处理 |
| --- | --- |
| 规则、Skill 发现或其他资源组合失败 | `ContextResourceError`，Agent 结束为 `resource_failed` |
| 摘要生成、预算或安全切点失败 | 保留原历史，Agent 结束为 `context_failed` |
| 快照读取或压缩提交失败 | 保留会话错误边界，Agent 结束为 `session_failed` |
| 用户取消 | 传播取消；已经开始的会话提交按 Session 规则完成后再退出 |

Memory 容错仅限自动检索：单条损坏或根目录不可读时可降级并记录诊断。它不吞掉 Session、项目规则或其他资源的失败；专用记忆工具的显式操作仍返回错误。

模型配置在下一次 Run 解析，ContextManager 接收该次 `LlmModel`。压缩、Memory 等非模型设置在 Agent 创建时传入；当前界面不提供这些设置的热更新，应按配置说明重启后端应用。
