# 会话系统设计

会话保存完整规范消息和可重放的历史树。Agent 只持有已绑定的 `Session`，入口使用 `SessionManager` 管理创建、列表、元数据和父子关系；JSONL 解析与文件锁统一由 `JsonlSessionStorage` 承担。

## 1. 存储布局与格式

默认根目录是 `~/.camel/sessions/`，也可在用户配置的 `session_dir` 中指定。相对路径始终相对于用户主目录解析，不随后端启动目录变化。

```text
sessions/
└── <parent-id>/
    ├── session.jsonl
    ├── tool-results/
    └── subagents/
        └── <child-id>/
            ├── session.jsonl
            └── tool-results/
```

会话 ID 只接受安全字符；子会话的真实位置由父子目录定位。子会话必须绑定父会话的工作区。目录内关联输出跟随所属会话，不写入用户项目目录。

当前 JSONL 格式版本为 `1`，一行一条完整 JSON 记录，以换行结尾：

| 记录类型 | 作用 | 主要数据 |
| --- | --- | --- |
| `session` | 唯一文件头 | 版本、会话 ID、工作区、名称、模型配置 ID、父会话和父工具调用 |
| `message` | 完整规范消息 | 用户文字、assistant 内容块或工具结果 |
| `compaction` | 历史上下文投影变更 | 摘要、`firstKeptEntryId`、压缩前估算量及摘要用量 |
| `session_info` | 追加元数据更新 | 名称、工作区、模型配置 ID、归档状态 |

除文件头外，每条记录含唯一 `id`、`parentId` 和时间。assistant 可以保存 Provider、请求/响应模型标识及用量；工具结果可以保存 `content_ref` 等 details。连接密钥不属于会话编解码字段。

运行事件 `AgentEvent`、流式 chunk、未完成的模型响应不写入日志。Run 内的 `sequence`、Run/Turn 坐标与历史节点 ID 是不同概念。

## 2. 原始历史、分支与模型快照

| Session 能力 | 返回内容 | 使用场景 |
| --- | --- | --- |
| `messages()` | 当前分支的原始完整消息 | 恢复分析、工具引用授权与审计 |
| `entries()` | 整棵树的历史条目 | 全树检查和分支定位 |
| `context_snapshot()` | 当前分支应用压缩后的只读消息投影 | 构造模型请求与生成压缩计划 |
| `branch(entry_id)` | 选择历史叶子或空根，并返回对应快照 | 从旧位置继续，后续追加形成新分支 |

投影按父引用向前追溯，不能简单将文件中出现过的所有消息都作为模型历史。兄弟分支不混入当前分支，一条分支上的压缩也不改变其他分支。

`branch()` 的选择保存在绑定 Session 对象内；默认新绑定跟随最新上下文。Python API 已支持分支选择，当前 HTTP/WebUI 尚无分支导航和历史编辑入口。

`ContextSnapshot` 是不可变数据，包含当前模型可见节点、消息和版本坐标。压缩使较早消息在模型投影中变为 `[Compacted History]` 摘要，但原始消息仍保留；原分支已登记的工具引用不会因压缩而失效。

## 3. 提交、并发与损坏处理

文件操作在线程中执行。单个存储对象按会话串行操作；跨对象、跨进程的读写通过 Portalocker 文件锁协调，写入使用独占锁，读取使用共享锁。写入一条记录后 flush/fsync，再释放锁。

ContextManager 按次借用 Session，先基于快照生成压缩计划，再调用 Session.compact；不直接接触存储或持有会话绑定。提交时在独占锁内重新投影历史，并比较原快照的 revision 和节点。并发消息或压缩会使旧计划失效；纯元数据变化不影响模型上下文版本。校验失败不追加旧摘要。

已经开始的磁盘写入和绑定会话游标更新需要一起完成。调用方取消会等待在途提交结束后传播，防止“日志已写入但 Session 叶子未更新”或过早释放锁。取消不回滚已经完成的记录。

读取严格校验版本、唯一文件头、记录 ID、父引用、目录与父会话关系。无结尾换行、非法 JSON 或未知格式会报损坏错误，不静默丢弃尾部。会话列表可以跳过坏会话并记录诊断，但显式打开或追加该会话仍失败，不自动修复用户数据。

这是文件追加协议，不是数据库事务：消息保存与外部工具副作用之间没有原子提交，也没有多个 Backend 进程对同一活动 Run 的所有权协议。

## 4. 中断后如何恢复

`run(prompt)` 保存一条新的用户消息；`resume()` 根据最后一个完整消息边界创建新 Run，不额外追加用户请求。空会话或已经正常以 `stop` 结束的会话不能直接续跑，应提交新任务。

| 原始分支尾部 | 恢复行为 |
| --- | --- |
| 用户消息后模型流中断 | 使用已保存用户消息继续请求 |
| assistant 工具调用已保存，部分结果缺失 | 为缺失调用补错误结果，说明副作用状态可能不确定，然后继续推理 |
| 完整工具结果之后 | 继续请求模型收尾或规划 |
| assistant 正常 `stop` 结束 | 拒绝恢复，要求新用户消息 |

补齐结果不会执行历史调用。Agent 在失败或取消时也尝试闭合工具消息链；进程重启后仍以同一恢复分析规则处理。是否需要重新修改文件或执行命令，应由模型和用户检查当前环境后决定，不能假设工具没有执行。

同一 Agent 的恢复分析和 Run 登记共用启动锁，避免在另一个活动 Run 期间读取过期边界。Backend 的 `RunService` 还在会话改绑、删除和启动之间做互斥检查。

## 5. 元数据、引用与删除

模型配置 ID 属于会话选择，具体凭据在每次 Run 解析。模型切换不修改历史消息中的审计模型；名称和归档变化也不改写已存在的消息记录。

工具结果读取资格来自当前原始分支的 `ToolResultMessage.details.content_ref`，还需通过所属目录和链接校验。子会话不能借用父会话或兄弟会话的结果读取资格。

SessionManager 计算后代到父会话的删除顺序。Backend 拒绝删除含活动 Run 的会话树，并关闭空闲 Agent；底层删除可能跨多个目录，不声称整棵树删除具有数据库事务语义。Memory 的生命周期独立，删除来源会话不会删除长期记忆。

旧平铺 JSONL 使用 [迁移脚本](../../scripts/migrate_flat_sessions.py) 做预览式复制迁移，不在运行时自动兼容、重写或删除旧文件。
