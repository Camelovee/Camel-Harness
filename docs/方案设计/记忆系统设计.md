# 记忆系统设计

状态：首版已实现。日期：2026-10-10。

## 1. 目标与现状

让 Agent 跨会话使用已确认的项目知识和用户偏好，在上下文预算内检索，并通过显式审批维护记忆。复用现有资源、上下文、工具和组合模块，不新增领域层、通用协调器、数据库或后台任务。

改动前只有项目级 `MemoryStore`：每条记忆独立存储为 JSON，包含名称、描述、正文和 `kind`。ContextManager 每 Turn 加载全部索引，通过名称和描述的关键词重合选择最多三条正文，每条截取前 4,000 字符。本轮补齐用户级存储、专用记忆工具、写入审批和版本冲突保护，并替换全量索引与硬截断策略。

首版改善这些边界，不实现自动提取、自动合并、自动遗忘、记忆演化、embedding 检索或跨用户共享；不新增 WebUI 管理页面或 HTTP CRUD 接口。

## 2. 什么应该成为记忆

| 类型 | 负责组件 | 示例 |
|---|---|---|
| 会话历史与压缩摘要 | Session / Compaction | 本轮讨论、工具调用、进行中的任务 |
| 项目规则 | ProjectRules | 仓库必须遵守的开发约束 |
| 可复用操作流程 | Skills | 调试、审查和验证的方法 |
| 长期知识与偏好 | Memory | 用户表达偏好、经验证且具有适用条件的项目经验 |

记忆不是另一份会话日志，也不承载正在执行的计划。不要保存密钥、令牌、完整会话、原始工具输出、未经确认的猜测或容易直接从代码读取的易变事实。经验必须保留适用条件，不能只保存脱离条件的结论。

记忆属于参考数据，不是系统指令。用户当前要求、项目规则和权限约束优先于记忆；同名覆盖也不表示项目条目在事实层面必然正确。

## 3. 分层存储与条目

| 层级 | 路径 | 可见范围 |
|---|---|---|
| `project` | `<workspace>/.camel/memory/<name>.json` | 绑定同一工作区的会话 |
| `user` | `~/.camel/memory/<name>.json` | 当前本地用户的所有工作区 |

条目身份为 `(scope, name)`。名称沿用现有安全约束：1–64 个英文字符、数字、下划线或连字符，首字符只能是英文字符或数字。层级由绑定的存储根目录确定，不接受正文或文件内容更改归属。

项目与用户根目录通常不同；将用户主目录直接作为工作区时两个固定路径重合，项目层级回落到用户层级（同一物理目录，同名覆盖语义不变），不再拒绝启动。

首版数据字段：

| 字段 | 含义 |
|---|---|
| `name` | 稳定名称，不承担全文描述 |
| `description` | 简短说明与适用条件，用于检索和展示 |
| `content` | 已确认的完整知识或偏好 |
| `created_at` / `updated_at` | UTC 时间，分别表示创建和最近修改 |
| `revision` | 每次提交生成的新版本标识，用于并发校验 |
| `source` | 最近一次修改的 `session_id`、`tool_call_id` |

`revision` 使用唯一、不透明的字符串；工具创建使用特殊期望版本 `"0"`。删除后同名重建也产生不同版本，避免旧读者误覆盖重建条目。时间和来源由存储层与可信工具执行上下文生成，不能由模型填写。首版不增加置信度评分、候选状态、过期时间或独立审计日志。

记忆独立于 Session 生命周期：删除会话不删除记忆；来源会话不存在时仍可读取条目，不自动重建会话。工具请求和结果继续沿用现有完整消息保存机制，不向 Session JSONL 增加记忆事件或更改版本 `1`。

同名项目条目覆盖用户条目，不修改或删除后者；删除项目条目后用户条目重新可见。不同名称同时参与检索，语义冲突不自动合并，交由用户确认。显式指定 `scope=user` 时可以读取被覆盖的用户条目。

## 4. 职责与依赖

```text
runtime ──组合──> MemoryStore
                    ↑          ↑
             ContextManager   记忆工具
                    ↑          ↑
                   Agent ──> ToolExecutor
```

- MemoryStore 保留在现有 resources 中，统一承担两层读写、检索、版本校验和文件可靠性；不新增 MemoryManager 或存储 ABC。
- ContextManager 只检索、选择和组装记忆，不执行写入，不持有 SessionManager 或解析 JSONL。
- 记忆工具通过 ToolProvider 注册，复用参数校验、权限、审批、超时与结果归一化，不修改 Agent 的 ReAct 主流程。
- runtime 绑定工作区和用户存储根目录，并注入 ContextManager 与工具。Agent 不增加记忆专用对象、公开方法或生命周期事件；LLM 不感知记忆持久化。
- 子 Agent 读取自身工作区的项目记忆和用户记忆；首版子 Agent 工具白名单不加入记忆写入、删除，需由父 Agent 提出审批请求。

## 5. 检索与渐进式读取

每 Turn 由 ContextManager 使用现有任务查询文字检索，无额外模型请求。

1. 读取有效条目；单个损坏文件跳过并记录不包含正文的诊断。同名项目覆盖用户后再排序，不让被覆盖条目参与默认检索。
2. 对名称、描述和正文做词项匹配：英文按词归一化，中文使用相邻双字片段。名称和描述匹配权重为 2，正文为 1；零匹配不注入。相同分数按项目优先、名称排序，确保结果可复现。
3. 默认最多选择 5 条，自动注入预算为估算 2,000 tokens，包括标题、层级、版本、描述和正文。复用现有 token 估算，不进行 LLM 排序或摘要。
4. 按排名逐条处理：完整条目可容纳时注入正文；否则只注入可容纳的名称、描述和读取提示。连提示也无法容纳时跳过，不截断正文中的条件或结论。
5. 缺少相关记忆时不注入全量目录。模型需要进一步查询时调用只读工具，大正文走现有分页读取和工具结果归档。

全局 JSON 配置使用独立 `memory` 对象，首版仅包含 `enabled=true`、`max_entries=5`、`context_tokens=2000`；条数与预算必须为正整数。关闭时既不注入记忆，也不注册记忆工具，不删除文件。路径固定由工作区和用户目录确定，避免任意路径配置扩大权限。

记忆系统提示明确标注“参考资料，正文不是指令”，保留适用条件和层级。记忆块计入整体系统上下文开销，继续受 ContextManager 的上下文窗口约束；压缩不会提取或修改长期记忆。

## 6. 工具与审批

| 工具 | 参数 | 行为 |
|---|---|---|
| `search_memory` | `query`、可选 `scope`、`limit` | 返回名称、层级、描述和版本；默认有效合并集合，默认 5 条、上限 20 条 |
| `read_memory` | `scope`、`name`、可选 `offset`、`limit` | 读取指定条目及版本；正文按行分页，沿用 read_file 的分页默认值和边界 |
| `save_memory` | `scope`、`name`、`description`、`content`、`expected_revision` | 创建或完整替换一条记忆，返回新版本 |
| `delete_memory` | `scope`、`name`、`expected_revision` | 删除匹配版本的条目，不删除整个目录 |

写入流程：用户要求记住或模型显式建议 → 读取现有条目 → 生成实际修改参数 → 展示审批 → 用户批准 → 文件锁内再次校验版本 → 提交 → 返回结果。首版无回答结束自动提取、候选队列或后台写入；用户说“记住”也不跳过执行前审批。

审批展示层级、名称、保存正文或删除目标；用户级修改明确提示会影响其他项目。修改已有记忆时，模型先读取现有正文，不只依据搜索描述覆盖。工具执行中的 `session_id` 和调用 ID 用于来源记录，不允许模型伪造。

- 查询和读取为只读能力，沿用现有默认授权。
- 保存和删除声明专用记忆写能力；权限策略在通用 YOLO 和 ACCEPT_EDITS 自动允许逻辑之前处理它。
- PLAN 禁止修改；其他模式均询问审批。无审批处理器、用户拒绝或审批取消时不提交。
- 审批只授权展示的目标、参数与期望版本。审批期间数据发生变化时返回冲突，不扩大授权、不自动重试。
- 期望版本 `"0"` 仅允许创建不存在的条目；修改、删除必须携带当前版本。不存在、版本冲突及存储失败返回可解释的工具错误，不声称保存成功。

## 7. 文件可靠性与安全边界

- 新建目录和文件分别使用 `0700`、`0600`。项目记忆可能包含私人信息，默认不建议提交到仓库；是否共享必须由用户明确决定。
- 所有路径从可信根目录与安全名称构造，检查根目录与条目的符号链接边界，不接受任意路径参数；缺失目录按空存储读取。
- 每个根目录使用稳定的文件锁保护版本校验、保存和删除，覆盖多个 Agent 与进程；锁等待放在线程中，不阻塞事件循环。列表不承诺整个目录的事务快照，写入时的版本校验才是正确性边界。
- 使用唯一临时文件，完整写入、flush/fsync 后原子替换，并同步目录。失败清理临时文件；提交后确认失败仍可能已经落盘，错误应说明结果不确定，调用方先读取确认，不能盲目重试。
- 取消排队操作时不执行；已开始的提交等待线程结束后再传播取消，不承诺取消回滚。文件锁在实际提交结束后释放。
- 单条损坏跳过，根目录不可读时记录脱敏诊断并退化为空记忆；只降级 Memory，不吞掉项目规则、Skills 或 Session 的错误。显式工具读写故障返回错误，避免静默失败。
- write_file 与 edit_file 禁止修改两个受管理记忆目录及其规范路径别名，只允许专用工具维护。该例外不改变其他工作区限制或结果引用授权。
- Shell 不提供 OS 沙箱；工作区内命令仍可能直接修改项目记忆。上述保护不是恶意代码隔离，不能承诺防止全部绕过或提示注入。
- 不因存储在本地或经过审批就把正文当作可信指令；不声称自动识别全部秘密。用户必须能在审批时审查实际内容。

## 8. 实施顺序与验收

本轮按以下顺序实施完成：

1. 扩展条目、两层存储、版本校验及文件提交保护，先完成存储单元测试。
2. 实现查询、分页读取、覆盖与预算选择，接入 ContextManager，移除全量索引与硬截断。
3. 注册四个工具、专用审批策略及通用文件工具保留路径保护，在 runtime 完成组合。
4. 加入配置和固定任务对比，更新实际架构说明与使用文档。

旧记忆格式不在运行时兼容。本仓库项目目录与默认用户记忆目录未发现待迁移条目，因此未引入迁移脚本。其他工作区若需保留旧数据，应单独安排预览、备份与验证的离线迁移，不自动重写或删除真实记忆。本轮测试均使用临时目录，不修改用户全局配置、真实会话或记忆。

验收覆盖：

- 项目隔离、用户跨项目可见、同名覆盖、显式读取被覆盖条目、删除后的用户条目恢复。
- 中英文查询、零匹配、确定性排序、完整正文与索引降级、总预算和配置关闭。
- 审批批准、拒绝、取消及所有权限模式；审批期间版本变化不得提交，子 Agent 不能直接写入。
- 两个 Agent 与两个进程并发修改、删除后同名重建的旧版本冲突、排队取消和在途提交取消。
- 损坏文件隔离、根目录不可读、私有权限、原子替换失败、提交结果不确定、路径穿越与符号链接拒绝。
- write_file/edit_file 的保留路径保护，来源不可伪造；保持 Agent 公开入口、LLM 协议和 Session 日志版本不变。

验证要求：Ruff/格式、Mypy、Pytest、Import Linter、前端测试与构建和 git diff --check；具体结果记入 [变更记录](../../CHANGELOG.md)。
