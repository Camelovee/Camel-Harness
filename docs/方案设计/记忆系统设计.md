# 记忆系统设计

Memory 保存跨会话可复用、已经确认的知识或偏好，按查询检索，在上下文预算内注入，并通过专用工具审批维护。它独立于会话历史和压缩摘要，不在回答结束时自动提取正文。

## 1. 与其他上下文的区别

| 内容 | 负责组件 | 例子 |
| --- | --- | --- |
| 本次对话与工具事实 | Session / Compaction | 任务进度、错误、继续执行所需的摘要 |
| 项目约束 | ProjectRules | 仓库根 `AGENTS.md` |
| 可复用操作流程 | Skills | 调试、审查、验证步骤 |
| 长期知识与偏好 | Memory | 有适用条件的经验、用户明确表达的偏好 |

适合保存的条目需要有适用条件和来源。密钥、令牌、完整私人会话、原始工具输出、猜测或可直接从当前代码读出的易变事实不应成为记忆。工具说明与审批承担内容审查，存储层不自动识别所有秘密。

Memory 正文是参考数据，不能覆盖当前用户要求、项目规则或权限约束。同名覆盖仅定义读取顺序，不证明内容一定正确。

## 2. 分层存储与身份

| 层级 | 路径 | 可见范围 |
| --- | --- | --- |
| `project` | `<workspace>/.camel/memory/<name>.json` | 绑定该工作区的会话 |
| `user` | `~/.camel/memory/<name>.json` | 当前本机用户的工作区 |

条目身份为 `(scope, name)`，scope 由可信存储根确定，不由文件正文决定。名称为 1–64 个英文字符、数字、下划线或连字符，首字符为英文或数字；Windows 还拒绝设备保留名。

默认合并视图中，同名项目条目覆盖用户条目；删除项目条目后，用户条目再次可见。显式 `scope=user` 可读被覆盖的条目。工作区就是用户主目录时，两层指向相同物理目录，两种层级操作同一份数据。

文件仅保存以下字段：

| 字段 | 语义 |
| --- | --- |
| `name` | 稳定名称，与文件名一致 |
| `description` | 检索说明与适用条件 |
| `content` | 完整知识正文 |
| `created_at` / `updated_at` | UTC 创建、修改时间 |
| `revision` | 每次提交新生成的 32 位十六进制版本 |
| `source` | 最近一次修改的 `session_id`、`tool_call_id` |

scope 不写入文件字段。时间、revision 和来源由存储层及可信 ToolContext 生成，模型不能通过工具参数伪造。旧 `name/description/content/kind` 文件格式不兼容，运行时不会自动改写或迁移。

Memory 生命周期独立于 Session；删除来源会话不删除记忆，不因来源缺失而重建会话，也不向会话 JSONL 新增记忆专用事件。

## 3. 组合职责

Backend 在 Agent 创建阶段按设置构造 MemoryStore、MemoryToolProvider 和其他可选扩展，经 `AgentExtensions` 注入。runtime 只完成对象组合，不直接导入具体 MemoryToolProvider。

- MemoryStore 负责两层读写、检索、版本校验及文件提交。
- ContextManager 只检索和选择正文，不执行写入，也不解析 JSONL。
- 记忆工具复用 ToolExecutor 的参数、权限、超时和结果归档。
- 子 Agent 复用对应上下文，只获得查询、读取白名单，没有保存、删除能力。

全局配置使用 `memory.enabled=true`、`max_entries=5`、`context_tokens=2000`。关闭时不注入记忆对象和工具，不删除磁盘条目；这些非模型设置在 Agent 构建时传入，当前按重启后端的方式生效。

## 4. 检索与上下文预算

每 Turn 按当前用户查询做确定性词项检索，不额外调用模型：

1. 加载有效条目，先执行同名覆盖；损坏条目跳过并记录不含正文的诊断。
2. 英文使用归一化词项，中文使用相邻双字片段；名称/描述匹配权重为 2，正文为 1。
3. 零匹配不返回；按分数降序、项目层优先和名称排序，默认最多选择 5 条。
4. 在估算 2,000 Token 总预算内，优先注入完整正文；放不下时尝试名称、说明、revision 和显式读取提示。
5. 连提示也放不下则跳过，不截断正文中的条件和结论，不注入全量目录。

预算包含 Memory 标题及索引，计入系统上下文总开销。估算复用 UTF-8 字节除以 3，不是精确 tokenizer。模型需要更多资料时使用搜索及分页读取；大正文沿用工具结果归档。

自动检索设置 `tolerant=True`，不可读或不安全的根目录可记录诊断并退化。显式查询不吞掉根目录故障，显式读取、写入和删除失败返回错误；这种降级不扩散到项目规则、Skills 或 Session。

## 5. 专用工具与审批

| 工具 | 主要输入 | 行为 |
| --- | --- | --- |
| `search_memory` | query、可选 scope/limit | 返回名称、层级、说明、revision，默认 5 条，上限 20 条 |
| `read_memory` | scope、name、可选 offset/limit | 从 0 起的行偏移分页，默认 400 行，上限 2,000 行 |
| `save_memory` | scope、name、description、content、expected_revision | 新建或完整替换条目 |
| `delete_memory` | scope、name、expected_revision | 删除批准的单条当前版本 |

创建使用 `expected_revision="0"`；更新、删除使用已读取的当前 revision。修改既有条目前先读取完整正文，不能只根据搜索摘要覆盖。

保存和删除声明 `memory.write`，权限策略先于通用 YOLO/ACCEPT_EDITS 规则处理：PLAN 直接禁止，其他模式全部询问。用户说“记住”也仍需执行前审批；无审批处理器、拒绝或取消时不能提交。

审批展示实际层级、名称、正文或删除目标。批准期间版本变化时返回冲突，不扩大授权、不自动重试。用户层修改影响其他工作区，需要在审批内容中明确。

## 6. 提交、取消和文件保护

保存/删除在根目录稳定 `.lock` 文件的独占锁内执行，覆盖多个 Agent 和进程。获得锁后重新读取版本，匹配期望版本才允许提交；删除后同名重建生成新 revision，旧读者不能误覆盖。

写入使用同目录唯一临时文件，完整写入并 flush/fsync 后原子替换，再同步目录。新目录和文件在 Unix 使用私有权限；Windows 依赖用户目录 ACL，目录同步适用平台实现。

替换或删除后的确认阶段仍可能失败，此时返回“结果不确定”，调用方应先读取确认，不得盲目重试。等待文件锁时取消会设置停止标记，尚未开始的提交不执行；已经开始的修改等待线程退出后传播取消，锁不会提前释放。

存储根、父路径、条目和锁文件拒绝符号链接或重解析点，安全打开还检查文件类型。通用 write_file/edit_file 禁止修改受管 Memory 目录及其别名，但 Shell 仍不是沙箱，不能承诺阻止程序直接修改这些文件。

当前没有自动提取、自动合并、过期淘汰、向量检索、独立审计库或 WebUI 记忆管理页面。
