# 上下文压缩设计

压缩将当前分支较早的模型可见历史替换为摘要，并保留近期完整消息区间。它生成上下文投影，不删除原始会话消息，也不提取长期 Memory。动态提示准备见 [上下文管理设计](上下文管理设计.md)。

## 1. 角色与配置

`CompactionEngine` 只返回不可变 `CompactionResult`：摘要、首条保留节点 ID、压缩前估算量及摘要用量。ContextManager 按次借用 Session 协调提交；Session 验证计划仍基于当前历史后才追加压缩事件，成功后 ContextManager 才返回可供 Agent 请求模型的消息。

配置在 `~/.camel/config.json` 的 `compaction` 对象中，独立于模型配置中的正常回答输出预算和窗口：

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `enabled` | `true` | 自动压缩开关 |
| `reserve_tokens` | `16384` | 压力阈值预留量 |
| `keep_recent_tokens` | `20000` | 从历史尾部选择近期消息的目标预算 |
| `min_messages` | `8` | 常规压力压缩的最少消息数 |
| `max_output_tokens` | `8192` | 首次摘要输出上限 |
| `retry_max_output_tokens` | `16384` | 摘要达到长度上限时重做的上限 |

所有预算校验为正值；运行时使用本次模型检查预留与近期历史／摘要预算的可行性，窗口随所选模型变化，不自动查询服务端能力。旧 compaction.context_window_tokens 在配置读取时迁入缺少窗口字段的模型，保存只输出新结构。

## 2. 两种触发方式

### 常规上下文压力

每 Turn 通过统一 Token 入口计算压力：优先使用当前分支中与当前 Provider、请求模型匹配的最近有效响应 `input_tokens + output_tokens`，再估算此后的新增消息。输入输出统计必须完整且总量大于零；不能再次添加其已覆盖的系统提示、工具定义、输出、缓存或 reasoning 细分量，也不能累加历史各轮 usage。

没有有效 usage 时，估算“全部历史 + 当前完整系统提示 + 工具定义”。历史按模型可见投影计算，不计 UI reasoning、响应模型审计字段和工具 details；文本与 JSON 统一使用 UTF-8 字节数除以 3 向上取整。这是近似值，不保证总是高估。

usage 不保存请求指纹；动态提示、Memory 或工具集合变化时存在误差。压缩后由快照的内存边界排除保留消息中的旧 usage，在新任务响应产生前使用全文估算。摘要请求自己的 usage 仅用于审计，不用于触发下一轮任务压缩。

窗口取本次 LlmModel 的 context_window_tokens；估算达到 `模型窗口 - max(reserve_tokens, 模型输出预算 + 4096)` 时评估压缩。未达阈值返回原上下文。即使压缩关闭或消息数少于 `min_messages`，超出安全预算也会明确失败，不让短历史绕过容量保护。

### Provider 首事件前报告超限

Adapter 将可识别的超限映射为 `StreamFailed.code=context_overflow`，LlmClient 不重发未改变的请求。只有该响应的第一个规范流事件就是这类失败时，Agent 才进入强制恢复；此前收到 `StreamStarted`、`UsageUpdated`、文本、思考或工具事件中的任意一种，就认为流已开始，即使尚无可见文字也不再进入恢复。

整个 Run 最多使用一次强制压缩恢复。它跳过常规压力阈值和最少消息数，仍尊重压缩开关、安全切点及预算。提交成功后重发同一 Turn 的请求，不重复保存用户消息、重跑历史工具或新增 Turn；仍消耗时间预算并记录已知用量。

## 3. 安全切点与摘要

1. 从快照尾部累计消息的内容估算（不使用整次响应 usage），选取目标近期预算；强制恢复也至少保留最后一个完整消息区间。
2. 移动边界，确保 assistant 的工具调用与对应结果全部进入摘要或全部保留。若末尾是工具结果，完整保留最后的工具调用区间，不能只留下无来源的结果。
3. 至少需要有可总结的较早消息和可保留的近期区间；没有安全切点时返回失败，不能随意截断正文。
4. 将选中历史投影为文本交给同一个本次 `LlmModel`，思考强度固定为 `low`；历史指令按待总结数据处理。
5. 摘要要求保留用户目标、约束、已完成工作、关键决策、工具事实和后续待办。已有摘要位于首条时，结合新增历史更新，不重复堆叠旧摘要。

摘要转录输入复用统一文本估算，保留原有额外 512 Token 预留。摘要请求的输入也受模型窗口限制；输出额度取摘要配置、模型输出预算、扣除完整摘要系统提示与输入及 4096 Token 安全余量后剩余窗口的最小值。摘要期间不执行工具。

## 4. 完整性、重做与提交

只有收到正常 `stop` 完成事件且正文非空，摘要才有效。缺少完成事件、流错误、空摘要或不支持的停止原因都不会生成提交计划。

首次以 `length` 结束时，最多重新生成一次，使用 `retry_max_output_tokens`，并要求更紧凑；不续写或拼接前次残片。实际重试预算被模型或窗口限制到不大于前次时，明确报告没有增长空间，不发送相同额度的重试。再次达到长度上限则结束。摘要失败不递归触发更多强制压缩；LlmClient 自身首事件前瞬时故障重试仍遵守统一策略。

生成后再次估算“摘要 + 近期消息 + 当前系统/工具开销”，必须小于安全预算。强制超限恢复还额外要求历史估算量严格缩小，避免提交无效摘要后再次发送同样大小的请求。

`tokens_before` 始终保存压缩前模型可见历史的内容估算，不包含系统/工具开销，不等同于触发压缩时的 usage 读数。

Session 在锁内比较原快照的 revision 与节点，使用稳定的 `firstKeptEntryId` 校验保留边界，再追加 `compaction` 记录并返回新快照。消息或压缩并发写入导致计划过期时拒绝；名称等元数据更新不导致计划过期。

## 5. 错误和取消

| 情况 | 结果 |
| --- | --- |
| 压缩关闭且超限、无安全切点、摘要不完整、压后仍超预算 | `context_failed`，原历史保留 |
| 强制重发再次超限，或后续 Turn 再超限 | 已用尽每 Run 恢复次数，`context_failed` |
| 已收到其他流事件后模型流失败 | 普通 Provider 失败处理，不进入强制恢复 |
| 快照读取、版本校验或压缩落盘失败 | `session_failed`，不伪装成 Provider 或工具失败 |
| 用户取消或 Run 超时 | 停止摘要/请求；已开始的 Session 提交按在途提交规则结束 |

每次摘要请求在 `finally` 统计实际收到的已知用量，失败、截断和取消也不漏计。跨两次摘要请求累加时，任一请求缺失某用量字段，总字段保持未知；不将未知数补零伪造成精确统计。Agent Run 的累计 Token 仅作审计，不等于上下文占用或费用账单。
