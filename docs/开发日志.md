# Camel Harness 开发日志

本文件从当前扁平架构版本开始记录。此前基于 DDD 的中间演进已压缩到本条基线，不再逐项保留；后续记录按自然日只追加。

## 2026-09-17

### 当前版本基线

主要变更：

- 完成 Python Harness Agent 的基础能力，包括流式 ReAct Loop、OpenAI/Anthropic、工具调用、权限审批、MCP、Skill、Memory、子 Agent、上下文压缩、CLI 和 WebUI。
- 会话统一存储在 `~/.camel/sessions/<session-id>/`，使用 `metadata.json`、`messages.jsonl` 和 `context.jsonl`；模型流结束后才追加完整 assistant 消息。
- Tool 定义改为 pi-agent 风格：`Tool` ABC 和相关契约位于 `backend.types.tool`，具体工具直接声明字段并实现 `execute()`。
- 删除 DDD 的 `core/application/domain/infra/adapter/bootstrap` 结构，改为 `agent`、`llm`、`session`、`tools`、`resources`、`compaction`、`types` 和 `api` 功能模块。
- 将原 `ReactAgent` 拆为 `AgentLoop`、`Agent` 和 `Harness`：低层循环不再依赖 Session、压缩和资源，Harness 通过上下文加载与完整消息提交回调协调产品能力。
- 使用单一 `runtime.py` 完成运行时装配，删除分区 wiring、重复事件 DTO 和 ApplicationService 转发层。
- 架构测试与 Import Linter 改为保护功能边界，不再保护 DDD 目录形状。

关键决策：

- 项目当前规模更适合 pi-agent 风格的功能模块架构；清晰调用链优先于限界上下文和分层完整性。
- 只在 Provider、存储、动态工具等真实变化点保留接口；单实现流程优先使用具体类或 callable。
- Agent Loop 只处理模型、工具、预算和事件；JSONL、动态资源和压缩持久化由 Harness 负责。
- 不保留旧 Python 导入路径和旧会话格式兼容代码。

验证结果：

- 后端类型检查源文件由 129 个减少到 87 个。
- Pytest 68 项通过。
- Ruff、Mypy 与 3 条 Import Linter 架构契约通过。
- OpenAI/Anthropic 契约、会话恢复、批量流保存、审批和工具循环测试保持通过。

后续事项：

- 完善 steering、follow-up、主动取消和运行阶段模型。
- 增加工具批次执行、Hook、MCP 重连和运行可观测性。
- 完成真实 Provider 冒烟、跨平台验证与发布准备。
