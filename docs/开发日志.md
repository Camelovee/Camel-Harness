# Camel Harness 开发日志

本文件从当前扁平架构版本开始记录。此前基于 DDD 的中间演进已压缩到本条基线，不再逐项保留；后续记录按自然日只追加。

## 2026-09-17

### 当前版本基线

主要变更：

- 完成 Python Harness Agent 的基础能力，包括流式 ReAct Loop、OpenAI/Anthropic、工具调用、权限审批、MCP、Skill、Memory、子 Agent、上下文压缩、CLI 和 WebUI。
- 会话统一存储在 `~/.camel/sessions/<session-id>/`，使用 `metadata.json`、`messages.jsonl` 和 `context.jsonl`；模型流结束后才追加完整 assistant 消息。
- Tool 定义改为 pi-agent 风格：`Tool` ABC 和相关契约位于 `backend.types.tool`，具体工具直接声明字段并实现 `execute()`。
- 删除 DDD 的 `core/application/domain/infra/adapter/bootstrap` 结构，改为 `agent`、`llm`、`session`、`tools`、`resources`、`compaction`、`types` 和 `api` 功能模块。
- 将原 `ReactAgent` 拆为 `AgentLoop`、`Agent` 和 `Harness`：低层循环不再依赖 Session、压缩和资源，Harness 通过上下文加载与完整消息提交回调协调产品能力。
- 使用单一 `runtime.py` 完成运行时装配，删除分区 wiring、重复事件 DTO 和 ApplicationService 转发层。
- 架构测试与 Import Linter 改为保护功能边界，不再保护 DDD 目录形状。
- 精简根目录 `AGENTS.md`，仅保留语言、核心调用链、LLM、工具、会话、安全、测试和文档约束。

关键决策：

- 项目当前规模更适合 pi-agent 风格的功能模块架构；清晰调用链优先于限界上下文和分层完整性。
- 只在 Provider、存储、动态工具等真实变化点保留接口；单实现流程优先使用具体类或 callable。
- Agent Loop 只处理模型、工具、预算和事件；JSONL、动态资源和压缩持久化由 Harness 负责。
- 不保留旧 Python 导入路径和旧会话格式兼容代码。

验证结果：

- 后端类型检查源文件由 129 个减少到 87 个。
- Pytest 68 项通过。
- Ruff、Mypy 与 3 条 Import Linter 架构契约通过。
- OpenAI/Anthropic 契约、会话恢复、批量流保存、审批和工具循环测试保持通过。

后续事项：

- 完善 steering、follow-up、主动取消和运行阶段模型。
- 增加工具批次执行、Hook、MCP 重连和运行可观测性。
- 完成真实 Provider 冒烟、跨平台验证与发布准备。

### Agent、Harness、Backend 与 CLI 拆分

主要变更：

- 将 Python 源码拆为 `camel.agent`、`camel.harness`、`camel.backend` 和 `camel.cli` 四个明确运行包。
- `camel.agent` 只包含通用 Agent Loop、LLM、稳定类型和工具执行核心；Session、Compaction、Resources、内置工具与完整组合迁入 `camel.harness`。
- FastAPI/SSE/浏览器审批与 Typer/终端/命令行审批分别迁入 Backend 和 CLI，两种入口互不依赖。

- 更新包发布配置、命令入口、测试导入和依赖守卫；不保留旧 `backend` 导入兼容层。

### Agent 与 LLM 双包重构

主要变更：

- 将 `camel_harness` 收敛为 `agent` 与 `llm` 两个功能包，删除额外的 `harness/` 和通用 `types/` 层级。
- `llm` 独立拥有规范 Message、序列化、`LlmRequest`、`LlmStreamEvent`、`ToolDefinition` 和 OpenAI/Anthropic Adapter，不反向依赖 Agent。
- `agent` 聚合完整 `Agent`、低层 `AgentLoop`、工具、Session、Compaction 与 Resources；Backend 和 CLI 统一调用 `Agent.run_turn()`。
- 删除轻量 Agent 与产品 Harness 的重复门面，完整对象图只由 `camel_harness.agent.runtime.build_agent()` 创建。
- Tool 运行契约迁入 `camel_harness.agent.tools.types`，子 Agent 的契约与本地实现合并到同一功能模块。
- 更新 README、项目架构、路书、WebUI 设计、项目约束、架构测试和 Import Linter 契约。

关键决策：

- 本项目本身就是 Harness Agent，无需再用 `Harness` 包装 `Agent`；单一 `Agent` 公共入口更容易理解和维护。
- Message 与模型可见的工具定义属于 LLM 边界；工具执行、权限和上下文属于 Agent 边界。
- 保留 AgentLoop 作为内部运行机制，用回调隔离 Session 和资源，而不把它扩展成第二个产品门面。

验证结果：

主要变更：

- `Agent` 改为私有持有运行依赖，公共方法只保留 `run_turn()` 和幂等 `close()`；删除未使用的 `update_options()` 与界面查询性质的 `list_workspaces()`。

- 子 Agent 直接复用同一个 `agent_loop()` 函数，不再创建轻量循环对象。

## 2026-09-18

### LLM 协议边界收敛

主要变更：

- 从 `LlmRequest` 删除 `session_id`、`turn_id`、`step_id` 和重复的 Provider 字段，只保留模型、消息、工具与生成参数。
- 将 `LlmStreamEvent` 收敛为 `type + data`；Provider Adapter 不再生成 Agent 序号或回传运行坐标。
- `agent_loop()` 在消费模型流时生成序号，并补齐 Session、Turn、Step 和 Provider 来源后投影为 `AgentStreamEvent`。
- `LlmClient` 增加只读 `provider_id`，删除请求与 Adapter 的重复 Provider 校验。
- 删除 `AgentOptions` 中已经失去用途的 Provider 副本，Provider 选择只存在于配置和绑定后的 `LlmClient`。
- `ToolDefinition` 删除 namespace 和限定名逻辑，只接收 Agent 工具投影后的最终模型工具名。
- 将 `message_to_dict()` 与 `message_from_dict()` 从 LLM 迁入 Session codec，使 LLM 不再感知 JSONL 持久化格式。
- 压缩引擎不再为摘要模型请求伪造 Session、Turn 或 Step 标识。
- 新增架构守卫，固定 LLM 请求、事件和工具定义的允许字段。

关键决策：

- LLM 层只描述模型调用及模型增量；Session、Turn、Step 和公开事件序号属于 Agent 运行时。
- 如果未来 Provider 需要缓存标识，应增加语义明确的模型配置，而不是复用 Agent Session ID。

验证结果：

- 当前行为测试与类型检查通过；完整质量检查结果将在本次开发结束时追加。

### 判别消息联合

主要变更：

- 参照 pi-agent 将 LLM 规范消息改为 `Message = UserMessage | AssistantMessage | ToolResultMessage`，删除通用 `Message` 容器与 `MessageRole`。
- 用户文本、assistant 内容块和单次工具结果分别拥有独立类型，避免非法的角色与内容组合。
- 将系统提示从 Message 序列分离到 `LlmRequest.system_prompt`，OpenAI 与 Anthropic Adapter 在各自协议边界完成投影。
- 每次工具调用保存一条 `ToolResultMessage`；Anthropic Adapter 按其协议需求合并连续结果，不污染内部消息模型。
- JSONL codec、会话投影、压缩器、Agent Loop 和 WebUI 同步迁移到新格式；不保留旧会话格式兼容。
- 增加架构守卫，防止恢复可表达非法状态的通用 Message 类。

验证结果：

- Ruff 格式与规则检查、Mypy 64 个源文件、Pytest 74 项和 4 条 Import Linter 契约通过。
- Python sdist/wheel 与 WebUI TypeScript/Vite 生产构建通过，`git diff --check` 无错误。

### LLM 结束原因

主要变更：

- 新增 `LlmStopReason(stop/length/tool_use)` 并作为 `AssistantMessage` 必填字段，与 Agent Turn 级 `StopReason` 分离。
- Anthropic Adapter 将 `end_turn/max_tokens/tool_use` 等原因规范化；OpenAI Adapter 结合响应状态、`incomplete_details` 和工具调用输出规范化结束原因。
- `agent_loop()` 校验 `stop/tool_use` 与工具调用是否一致，并将长度截断投影为 Agent `model_length` 失败终态。
- 截断响应中的工具调用不会真正执行；系统会写入错误工具结果，确保持久化消息链符合 Provider 协议。
- JSONL 格式增加 assistant `stop_reason`，不兼容缺少该字段的旧消息。
- 压缩摘要只接受 `stop` 结束，避免使用被截断的摘要替换上下文。

- 新增 Provider 结束原因映射和截断工具安全测试；当前 Pytest 77 项通过。
