# 会话性能基准

用于判断全量 JSONL 重放的成本，不代表真实任务成功率，也不是跨机器性能承诺。

## 复现

```bash
uv run python scripts/benchmark_session.py
```

默认测试 100、1,000、10,000 条初始完整消息，每种规模重复三次，报告中位数及原始样本。每次重复使用全新临时会话并自动清理，不访问用户会话、不调用模型，也没有 CI 耗时门槛。

使用正式 Session 编码器批量构造交替的 User/Assistant 历史，避免建档的重复重放混入测量。追加测量使用正式 Session 接口；快照、元数据、列表在追加一条完整消息后测量。列表每次只有一份日志，不代表大量会话的列表成本。消息较短，没有压缩、工具调用或历史分支。

## 后续决策

本轮保留全量重放和日志版本 1，不增加缓存或第二份上下文存储。当前短消息基准未证明必须引入缓存；如果真实使用出现瓶颈，先测多会话列表、大工具消息和历史分支，再评估 Session 内增量投影与失效机制。
