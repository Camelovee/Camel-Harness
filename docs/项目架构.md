# 项目架构

目标：保持轻量、单向依赖，让 Agent 专注 ReAct 编排，入口、模型协议与持久化各自独立。

## 目录与依赖

```text
src/
├── camel_harness/
│   ├── llm/          # 规范消息、流事件、消息组装、官方 SDK 适配
│   └── agent/
│       ├── agent.py  # Run/Turn 编排、取消、恢复与保存时机
│       ├── events.py # 生命周期事件与内部顺序投递
│       ├── state.py  # 运行状态、选项与用量
│       ├── runtime.py # 唯一完整组合模块，包含子 Agent 委派运行器
│       ├── config.py # 用户级 JSON 配置
│       ├── tools/    # 工具注册、执行、权限与结果归档
│       ├── session/  # JSONL 编解码、历史树与会话管理
│       ├── context/  # 动态上下文准备与压缩计划
│       └── resources/ # 项目规则、Skill 与 Memory
├── camel_backend/   # HTTP/SSE、会话用例、Web 审批与配置
└── camel_cli/       # 命令行与终端审批
```

依赖沿 `Backend / CLI → Agent → LLM` 流动；Backend 与 CLI 互不依赖，LLM 不感知 Agent、Session 或运行坐标。不新增独立 AgentLoop 或通用协调器。

## 职责边界

| 组件 | 负责 | 不负责 |
| --- | --- | --- |
| Agent | 单 Session/Workspace 的 Run 与 Turn、工具调用、事件坐标、保存点 | JSONL 格式、Session CRUD、资源检索策略 |
| LLM | 消息与请求协议、官方 SDK 适配、响应组装、流完整性校验 | 审批、持久化、Session/Run/Turn ID |
| ContextManager | 提示组装、检索文字、上下文开销与压缩计划 | 持有 Session、读写日志、会话 CRUD |
| Session | 当前分支消息、上下文快照与压缩提交 | Agent 事件、模型调用、资源检索 |
| SessionManager | 会话 CRUD、父子关系、目录定位 | ReAct 编排 |
| Tools | 参数校验、权限审批、超时、执行与结果归一化 | 驱动 Agent 循环 |
| Backend / CLI | 入口校验、会话定位、交互和输出投影 | 复制 Agent 主流程 |

## 运行流程

1. 入口定位绑定单个会话的 Agent，订阅事件并启动 `run()` 或 `resume()`。
2. Agent 保存用户输入，读取 Session 快照。
3. ContextManager 每 Turn 从基础提示重新组装动态资源，返回提示及可选压缩计划。
4. Agent 通过 Session 校验并提交压缩，使用已提交快照构造 LLM 请求。
5. 模型增量实时通知；流完整结束后保存 assistant 消息，再执行工具并保存完整结果。
6. Turn 结束后消费 steering FIFO，继续推理或发送唯一终态 `agent_end`。

一个 Agent 同时只有一个 Run，并持有执行任务；订阅者不驱动运行。取消传递至 LLM、审批和工具，未完成 assistant 不保存；缺失工具结果补错误消息，恢复不重试历史副作用。

## 协议与存储

- 规范消息为 `UserMessage | AssistantMessage | ToolResultMessage`，系统提示单独传入请求。
- `AgentEvent` 为具体生命周期事件的判别联合，运行坐标和 Run 内递增 sequence 由 Agent 注入；Provider 增量仅位于 `message_update.assistant_event`。
- Agent 直接构造具体事件，事件模块不读取或修改 AgentRun；完整消息先提交 Session，再构造完成事件。非流式消息共用保存路径，工具阶段返回已保存的结果集合；`tool_execution_start` 表示开始处理调用，包含审批与拒绝，不保证实际执行。
- `resume()` 的空闲检查、恢复计划读取和 Run 登记共用启动锁，避免并发启动使用过期恢复边界。
- LLM `stop_reason` 与 Run 终态独立。截断调用不执行，每 Run 最多一次恢复 Turn；流失败仅在首事件前的瞬时错误可重试。
- Adapter 将 SDK 请求及流错误中的上下文超限映射为 `StreamFailed.code = context_overflow`；Client 不重发未修改的超限输入。Agent 只对首个流事件前的超限在当前 Turn 强制压缩并重发一次，次数在整个 Run 内共享，消息 ID 与事件序号保持连续，不重存用户输入或重跑历史工具。流已开始或非超限错误不进入恢复。
- 强制压缩跳过压力阈值与最小消息数，仍尊重压缩开关与安全切点；历史末尾为工具结果时完整保留对应调用区间。摘要必须完整、缩小历史且满足预算，提交成功才重发；无安全计划、摘要失败或重试后仍超限使用 `context_failed` 终态，落盘失败保留 `session_failed`。摘要自身超限不递归恢复，已知用量、取消、Run 时长与 Turn 上限继续遵守原有规则。
- Session 日志版本为 1：会话头后追加完整消息、压缩和元数据更新；`id/parentId/timestamp` 构成历史树，不持久化 AgentEvent 或 chunk。
- `messages()` 返回原始分支历史，`context_snapshot()` 返回压缩后的模型上下文。压缩提交校验快照与保留边界，不删除原消息。
- 顶层会话位于 `~/.camel/sessions/<id>/session.jsonl`，子会话递归位于父目录 `subagents/<id>/`；大结果通过结构化 `content_ref` 引用所属会话文件。

## 扩展与可靠性

工具实现 `Tool` ABC，通过 `ToolProvider` 注册；模型只接收最终 `ToolDefinition`。Skill 只提供发现与三层按需加载，不自动评估或改写。

资源由 `runtime.py` 创建和关闭，子 Agent 借用共享 LLM。事件投递保持顺序和有界背压，观察者故障不撤销保存。会话提交与文件修改等待已开始的 I/O 完成后传播取消；写入与编辑共享进程内文件队列并使用原子替换。

McpManager 的唯一连接任务拥有 SDK 上下文，从连接、握手到关闭都在同一任务内完成；失败 Server 就地清理，调用方取消关闭等待不会取消清理。LocalSubagentRunner 位于 runtime，工具模块只通过委派回调调用，不反向构造完整 Agent。

普通结果和 Shell 分块归档均通过 ToolResultStorageError 传播基础设施故障，Agent 终止 Run 并补齐工具链，不重新执行命令。read_file 保留工作区读取，并通过 Session.tool_result_paths 的当前原始分支投影读取自身已登记结果；工作区外的未登记、跨会话、穿越和符号链接引用拒绝，写入和编辑边界不变。

Session 仍采用全量重放，不新增缓存；离线测量及环境限制见 [会话性能基准](会话性能基准.md)。

配置统一为 `~/.camel/config.json`，压缩参数独立。依赖边界由 Import Linter 与架构测试保护；项目不承诺多进程接管、工具 exactly-once 或 OS 沙箱。
