# Camel Harness 路书

> 本文只描述产品与工程演进顺序，不替代[项目架构](项目架构.md)中的边界约束。
>
> 功能核对基线：2026-10-07。当前版本定位为单机、本地工作区、单 Agent 单活动 Run 的 Agent Runtime。

配置入口统一为全局 `~/.camel/config.json`，CLI、Backend 与真实评测共享；不再读取环境变量和 `.env`。WebUI 自定义模型继续使用本机设置文件，缺省凭据从 JSON 回退。

WebUI 已提供配置文件默认模型的可视化表单，支持 Provider、模型 ID、密钥和接口地址设置，脱敏读取、校验保存及文件版本冲突检查；保存后重启后端生效。

入口启动时若缺少 `config.json`，加载器自动创建私有权限的默认配置，保留已有文件；首次可通过 WebUI 配置默认模型。

2026-10-08：全局配置切换为严格 JSON，压缩参数收敛到独立 `compaction` 对象；新增一次性 YAML 转换脚本，运行时无兼容。压缩按 token 预算保留近期历史，独立摘要预算、一次截断重试、空摘要与不完整流拒绝、取消传播、跨尝试用量计入 Run，以及系统提示/工具定义和压缩后大小检查已实现。失败保守终止 Run 并保留原历史；软阈值失败降级和上下文超限自动恢复尚未实现，不声称已具备。下一步用当前提交重跑真实压缩任务，记录截断率、摘要信息保留与 token 成本，而非只提高上限。

## 1. 项目目标与边界

2026-10-09：按独立执行计划收敛职责，分离消息保存与事件通知、隔离订阅者故障并统一终态；压缩估算归 ContextManager，删除累计 token 终止预算。子 Agent 按终态回传最终回答，父任务取消时关闭；入口写操作与 Run 启动互斥，工厂不再创建会话。删除 ID 值对象、校验器注入、上下文转发与审批查询抽象，保持现有目录和树 JSONL 格式。

Camel Harness 面向代码工作流，目标是提供一个可观测、可恢复、可扩展的工具型 Agent Runtime，而不是只提供聊天界面。

核心调用链固定为：

```text
Backend / CLI -> Agent -> LLM
                   +----> Tools
                   +----> Session / Context / Resources
```

当前版本明确保持以下边界：

- 一个 `Agent` 只绑定一个 `Session` 和一个 `Workspace`；
- 一个 `Agent` 同时最多运行一个 Run；
- 单文件会话日志的 `message` 记录保存完整规范消息，是会话恢复的事实来源；
- LLM 增量只用于实时事件，不作为不完整 assistant 消息落盘；
- Backend 和 CLI 只负责入口、协议投影和交互，不复制 Agent 主流程；
- 暂不承诺多用户、高并发、多进程接管或副作用工具 exactly-once 执行。

## 2. 当前已实现能力

### 2.1 Agent Runtime

- 多 Turn 流式 ReAct Loop；
- `Agent` 统一编排 Run、Turn、上下文、LLM、工具和消息保存；
- 单 Agent 单活动 Run 约束；
- Turn 数、单次输出上限和最大运行时长限制；累计用量仅作审计；
- 不再限制固定次数的合法重复工具调用，循环由 Turn 数与时长约束；
- 正常完成、模型长度截断、Provider 失败、超时和取消等 Run 终态；
- `agent_end` 作为正常、失败和取消 Run 的唯一终态事件。

### 2.2 LLM 与消息协议

- Anthropic 与 OpenAI 官方 Python SDK 适配器；
- 厂商无关的 `UserMessage | AssistantMessage | ToolResultMessage`；
- 独立的 `LlmRequest`、`LlmStreamEvent` 和 `ToolDefinition`；
- LLM 流协议采用九种具体 dataclass 的判别联合；Provider、Agent、压缩、子 Agent、CLI 与 WebUI 使用明确属性，不保留旧 data 字典接口或 partial 消息快照；
- 文本、思考、Token 用量和工具调用增量统一映射；
- `LlmStopReason` 统一表达 `stop`、`length` 和 `tool_use`；
- `length` 结束时禁止执行可能被截断的工具参数；
- LLM 层不携带 Session、Run、Turn 和 Agent 事件序号。

### 2.3 Agent 事件与实时传输

- `AgentEvent` 判别联合覆盖 Agent、Turn、Message、Tool 和 Approval 生命周期；
- Agent 持有唯一 Run 任务，入口通过 `subscribe()` 观察事件；
- Provider 增量统一封装在 `message_update.assistant_event`；
- 一个 Run 内的 `sequence` 单调递增；
- FastAPI + SSE 实时输出；
- Backend 使用有界队列桥接订阅事件，SSE 断开时显式中止 Run；
- WebUI 支持消息增量、思考过程、工具轨迹和审批卡片；
- WebUI 空白新对话可直接发送消息，首次发送在后端当前用户主目录创建会话；
- WebUI Composer 支持目录选择与输入法 Enter 防误发，会话可重命名；工具轨迹收敛回对话流，顶部展示有来源的 Token 用量；
- WebUI 支持同页多会话并行，切换会话保留执行和各自草稿；侧栏显示运行、审批及未读终态，暂停与审批独立定位会话；页面刷新/关闭仍取消连接对应的 Run，不提供后台接管；
- CLI 支持文本流式输出和工具调用状态展示。

### 2.4 工具与安全基础设施

- `Tool`、`ToolCall`、`ToolContext`、`ToolResult` 契约；
- 显式 `ToolProvider` 注册和工具名称冲突保护；
- JSON Schema 参数校验；
- Default、Accept Edits、Plan、YOLO 四种权限模式；
- Web 浏览器审批和 CLI 审批；
- 工具超时、异常归一化和大结果落盘（主/子 Agent 均写入所属会话的 `tool-results/`，随会话删除）；
- Agent 绑定单个 Session，入口层 SessionManager 管理 CRUD 和父子关系；规范消息先保存再通知外部订阅者，Session 不依赖 AgentEvent，不引入独立 AgentLoop 或新的存储抽象；
- 每次完整回答持久化 Provider、请求/实际响应模型及 usage；缓存和推理用量只作为明细，不重复计入总量。大工具结果以 details.content_ref 结构化保存，HTTP/SSE 和 WebUI 历史回放保留审计数据，未知用量不伪造；
- `read_file`、`write_file`、`edit_file`、`run_shell` 四个内置工具；
- 工作区路径限制、软链接逃逸检查和原子文件写入；
- Shell 超时、取消、进程终止和危险命令基础拦截；
- MCP stdio Server 工具发现、调用和关闭；
- Skill frontmatter 发现、正文按需加载、支持文件按需读取；随包内置四个通用 Skill，支持项目级和用户级目录，同名按内置 > 项目级 > 用户级选择；不维护 Skill 评估或演化状态；
- Explore、Plan、General 三类隔离子 Agent；
- 子 Agent 工具白名单和禁止递归委派；
- 子会话记录父会话及委派工具调用 ID，删除父会话时级联清理全部后代。

### 2.5 会话、上下文与恢复

- 每会话一目录一份 JSONL，子会话递归存于父目录 `subagents/`；日志包含会话头、完整消息、压缩与元数据更新记录；
- 会话文件私有权限、并发元数据更新互斥、列表坏文件隔离和流式元数据投影；
- 会话创建、查询、列表、更新、归档和删除；
- 顶层会话列表排除委派子会话，子会话可按 ID 查询；
- Session 持久化采用四种具体 SessionEvent、重新从 version=1 编号的 id/parentId 历史树；Session.entries 查看全部分支，Session.branch 选择叶游标，messages/ContextSnapshot 沿当前分支恢复，压缩按 firstKeptEntryId 定位并校验计划快照；不兼容旧区间日志，旧文件保留；
- 上下文压力触发的历史摘要；
- ProjectRules、Skill 元数据索引和 Memory 动态系统上下文；
- `steer()` 运行中输入 FIFO；
- `abort()` 主动取消并向 LLM、审批和工具传播；
- `wait_for_idle()` 等待终态和清理完成；
- `resume()` 从完整消息边界创建新 Run；
- 缺失工具结果自动补充错误消息，但不自动重试历史副作用工具；
- 中断时不保存未完成 assistant 消息。

### 2.6 工程质量与入口

- `camel_harness` 只包含 `agent` 和 `llm`；
- Backend 与 CLI 为独立顶层包；
- Import Linter 和架构测试保护单向依赖；
- 217 项 Pytest 测试与 15 项前端测试通过（2026-10-09，本地工作树）；
- Ruff、Mypy、Import Linter、WebUI TypeScript/Vite 构建通过，CI 纳入前端测试；
- Typer CLI、FastAPI API 和 React WebUI 均可运行。

## 3. 投递前优先级

目标岗位为 Agent 开发 / Agent Runtime / Applied AI Engineer，而非多租户 Agent 平台。公开的 [Codex Core Agent 岗位说明](https://openai.com/careers/applied-ai-engineer-codex-core-agent-san-francisco/)强调真实编码任务、评测、工具与上下文策略、失败分析，以及 token、延迟、可靠性和成本；[Evals 工程岗位说明](https://openai.com/careers/backend-software-engineer-%28evals%29-san-francisco/)也强调可复现评测与迭代。以下排序是基于这些信号和本项目现状作出的工程判断，不是岗位的统一要求。

| 能力 | 当前状态 | 投递价值 |
| --- | --- | --- |
| ReAct、规范事件、Provider、工具审批、MCP、子 Agent、Skill、压缩、恢复 | 已实现并有自动化测试 | 可作为项目主体，避免继续堆同类功能 |
| 每会话目录、递归子会话、JSONL 恢复 | 已实现；旧平铺日志需一次性迁移，不做运行时兼容 | 展示状态边界和数据完整性 |
| 可复现 CI、干净安装、真实 Provider 演示 | CI 配置、干净 wheel 安装、Anthropic 协议兼容端点演示已完成；远端 CI/OpenAI 实测待验证 | 首要交付缺口 |

### P1：评测与可观测性

目标：从 P0 的基线出发，证明每次 Agent 改动带来的收益与代价。

任务：

1. 将固定任务扩展到较长的真实仓库任务，划分成功、部分成功、超时和错误；保留任务输入、评判规则与可复现环境。
2. 记录任务成功率、工具调用成功率、Turn 数、Token、基于固定价格快照的估算成本、端到端延迟和恢复成功率，并保存基线与回归趋势。
3. 对 Skill、上下文压缩和工具策略做至少两组 A/B 实验；不因主观观感宣布“效果提升”。
4. 增加 Run、Turn、Tool、Provider、Compaction 的结构化诊断日志，关联事件坐标但默认不记录密钥或完整敏感内容。
5. 记录工具耗时、审批等待时间、Provider 重试次数、失败分类和压缩前后大小；为失败任务生成简短轨迹报告。

完成标准：

- 同一提交和配置下重复运行可得到可解释的结果波动；
- README 中展示基线、改动前后对比和失败样本，而不只列功能；
- 任意一次失败都能定位到 Run、Turn、Tool 或 Provider 阶段。

### P1：可靠性补强

目标：覆盖当前 Runtime 最容易在真实使用中出问题的边界。

任务：

1. 增加 Provider 断流、超时、限流、认证失败和响应格式异常测试；
2. 在现有“首事件前重试”边界内增加错误分类、指数退避和随机抖动；绝不在已输出增量后透明重试。
3. 接入上下文溢出错误的自动压缩与一次重试；当前只有 `CONTEXT_OVERFLOW` 压缩触发类型，Agent 尚未接入自动恢复。
4. 增加 SSE 消费中断、进程重启测试，并为 JSONL 尾部损坏提供安全诊断与人工修复流程；
5. 增加相同 Session 并发 HTTP 请求、重复提交和子会话级联删除测试；
6. 明确工具副作用未知时的恢复提示和人工确认流程。

完成标准：

- Provider 暂时失败不会产生重复 assistant 增量；
- 工具调用链在取消、断流和进程重启后仍然可解释；
- 会话损坏可以被发现并给出安全诊断，而不是静默丢失历史。

## 4. 后续能力优先级

P2 只有在 P0/P1 的交付与评测闭环完成后才实施；P3/P4 面向特定岗位或产品场景，不作为普通 Agent 开发岗位简历的投递门槛。

### P2：工具编排与扩展能力

目标：提升 Agent 对复杂任务的执行效率和扩展性。

任务：

- 根据评测瓶颈决定是否支持只读工具并行；副作用工具仍默认串行；
- 只有真实扩展需求出现时才增加 before/after tool hooks 与工具进度事件；
- 支持下一 Turn 动态切换模型、Token 预算和 thinking 配置；
- 增加 MCP 连接状态、重连、超时和健康报告；
- 为实际接入的工具增加必要的能力声明；只有重试场景需要时才设计幂等键和副作用确认协议。

完成标准：

- 新工具无需修改 Agent 主流程；
- 并行策略不会破坏消息顺序、权限和取消语义；
- MCP 或工具故障可以单独隔离，不拖垮整个 Runtime。

### P2：安全边界

目标：将当前“本地工具保护”提升为可解释的执行安全边界。

任务：

- 先建立威胁模型、恶意路径、命令绕过和提示注入测试，明确当前工作区限制不等于进程沙箱；
- 若目标岗位要求部署执行不可信代码，再使用容器或受限沙箱执行 Shell；
- 限制 CPU、内存、进程数、磁盘空间和运行时长；
- 控制网络访问和可继承环境变量；
- 过滤 API Key、Token 等敏感信息；
- 为 MCP Server 启动和外部调用增加授权；
- 输出工具审计日志和人工审批记录。

完成标准：

- 明确区分“工具风险控制”和“真正的沙箱隔离”；
- 高风险工具具备可追踪、可拒绝、可审计的执行链路；
- 安全策略不会依赖单一正则黑名单。

### P3：本地生产化运行时（平台/后端岗位定向）

目标：支持长任务、断线、进程重启和多用户访问。

任务：

- 增加用户认证、Session 所有权和 Workspace 授权；
- 增加请求限流、并发限制和资源配额；
- 将活动 Run 和任务状态持久化，支持后台运行；
- 增加 SSE 断线续传、事件游标和历史增量读取；
- 增加请求幂等键，防止浏览器重试重复创建 Run；
- 为多进程部署引入共享状态和事件总线；
- 将内存审批迁移到可恢复的持久化任务状态；
- 增加 readiness、依赖检查和优雅停机。

完成标准：

- 浏览器断线后可以重新连接并继续观察 Run；
- 服务重启后可以识别活动任务和待处理审批；
- 不同用户不能读取或操作彼此的 Session、Workspace 和审批请求。

### P3：会话与知识能力（有分支需求再做）

目标：让长周期开发任务具备可分支、可审计、可回溯的历史管理能力。

任务：

- Session 分支及 leaf 游标核心已实现；后续按需提供 WebUI/HTTP 导航，并在入口阻止运行中切换；
- 手动压缩、压缩预览和压缩回滚；
- 会话导出、审计导出和只读损坏诊断；
- 记忆条目的引用来源、更新时间和冲突处理。

完成标准：

- 用户可以从任意历史分支创建新任务；
- 压缩不会破坏原始消息和审计记录；
- Memory 和 Session 的来源与修改历史可追踪。

### P4：模型策略与发布生态

目标：形成可持续扩展的 Agent 平台能力。

任务：

- 模型能力注册表和 Provider feature detection；
- Provider fallback、模型路由和成本策略；
- 模型价格配置与按 Run 成本估算；
- 插件隔离、版本约束和健康检查；
- macOS/Linux 跨平台验证；
- Docker 镜像、发布包和版本升级策略；
- 性能基准和压力测试。

完成标准：

- 新 Provider 可以只实现 LLM 协议和事件映射；
- 模型降级和成本上限有明确策略；
- 发布物可以在干净环境中安装、启动和升级。

## 5. 暂缓能力与引入条件

以下能力当前不进入 Agent Core，只有出现明确产品需求时再评估：

- Run 完成后的 Follow-up 队列；
- 持久化 steering Inbox；
- 多进程共享活动 Run；
- 后台任务调度器；
- Provider 服务端生成任务的暂停与接管；
- 通用 Event Store；
- 为单一实现提前建立多层 Service、Port 或 Repository 抽象。

引入这些能力前，必须先说明它解决的实际场景、持久化边界、并发模型、取消语义和故障恢复方式，避免为了“看起来完整”扩大 Agent Core。

## 6. 推荐实施顺序

```text
当前基线
   |
   v
P0 可交付基线：CI / 最小 Evals / Demo / 发布验证
   |
   v
P1 可量化改进：评测对比 / 故障轨迹 / 可靠性补强
   |
   v
P2 按评测结果补能力：工具策略 / MCP 诊断 / 安全测试
   |
   v
P3 岗位定向：认证 / 后台任务 / 断线续传 / 多进程
   |
   v
P3 需求驱动：分支 / 压缩管理 / Memory 版本化
   |
   v
P4 模型策略与发布生态：Fallback / 成本 / 插件 / 跨平台
```

每个阶段都必须同时交付：

1. 运行时代码；
2. 行为测试或评测任务；
3. 文档和限制说明；
4. 可复现的验证命令；
5. 对外接口或会话格式变化时的迁移说明。
