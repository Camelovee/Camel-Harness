# Camel Harness 路书

## 当前状态

当前版本已完成从 DDD/多层端口结构到 pi-agent 风格功能分包的迁移：

- `camel_harness` 仅保留独立 `llm` 包和完整 `agent` 包；
- 调用链统一为 `Backend/CLI -> Agent -> LLM`，ReAct 循环属于 Agent 内部实现；
- 不再区分 Agent 与 Harness，`Agent` 统一编排会话、资源、压缩和运行生命周期；
- Backend 与 CLI 是独立顶层包，彼此不依赖；
- OpenAI/Anthropic、JSONL 会话、SSE、审批、MCP、子 Agent 委派、Skill/Memory 动态上下文和压缩行为保持可用。

## 已完成里程碑

### M1：核心 Agent Runtime

- 流式多 Turn ReAct Loop；
- 规范消息、工具调用和事件；
- Turn、token、时间与重复调用保护；
- 完整消息保存点与异常流保护。

### M2：Provider 与会话

- Anthropic 默认 Provider；
- OpenAI 与 Anthropic 官方 SDK Adapter；
- 用户级 `~/.camel/sessions/`；
- `metadata.json`、`messages.jsonl` 和 `context.jsonl`；
- 会话 CRUD、工作区过滤和恢复。

### M3：工具与安全

- Tool ABC 与直接字段式定义；
- 默认提供 read/write/edit/shell 四个核心工具与隔离的 `delegate_task`；
- 参数校验、权限模式、审批、超时和大结果落盘；
- 显式 `ToolProvider` 注册与 MCP 扩展。

### M4：上下文与界面

- 项目规则、Skill、Memory 动态上下文；
- 追加式上下文投影与历史压缩；
- CLI、FastAPI SSE 和 React WebUI；
- thinking 流展示和会话工作区界面。

### M5：架构简化

- 删除 DDD 和 ApplicationService 转发层；
- 将 FastAPI Backend 与 Typer CLI 拆为独立入口包；
- 合并同一变化原因的小型协议与实现；
- 删除单实现抽象和旧导入兼容层；
- 使用架构测试和 Import Linter 保护真实依赖边界。

### M6：Agent 与 LLM 双包结构

- `camel_harness.llm` 独立拥有 Message、模型协议、工具定义和厂商 Adapter；
- `camel_harness.agent` 聚合完整 Agent、工具、会话、压缩和资源；
- 删除额外 Harness 门面、`harness/` 包和通用 `types/` 包；
- 唯一完整组合点迁移为 `camel_harness.agent.runtime.build_agent`；
- 固化 `Backend/CLI -> Agent -> LLM` 的单向依赖。
- Agent 公共表面收敛为 `run()` 与 `close()`，入口层独立持有 Session、工作区选择和审批能力。
- LLM 请求和事件移除 Session、Run、Turn、Provider 路由与 Agent 序号，运行坐标统一由 Agent 注入。
- ToolDefinition 只保留模型可见字段，JSONL 消息编解码归入 Session。
- 规范消息收敛为 `UserMessage | AssistantMessage | ToolResultMessage`，系统提示从会话消息分离到 `LlmRequest.system_prompt`。
- OpenAI 与 Anthropic Adapter 各自负责将判别联合投影为官方 SDK 协议；Anthropic 仅在边界处合并连续工具结果。
- `AssistantMessage` 保留规范化 `LlmStopReason`，与 Agent Run 级终止原因分离。
- Agent 内部循环可识别正常停止、工具调用和长度截断，禁止执行截断响应中的工具参数。
- `ContextManager` 收敛到 `agent/context/`，统一提供动态系统上下文和压缩计划；Session 仍独立管理消息、元数据与持久化投影。
- `CompactionEngine`、`CompactionResult` 和 `CompactionTrigger` 合并到 `agent/context/compaction.py`，删除只有单实现的顶层 `compaction/` 目录。
- 权限决策使用唯一默认规则，删除无实际多实现的 `PermissionDecider` 注入点，仅保留 Web/CLI 审批扩展边界。
- 删除独立 `agent_loop.py` 及公开 `agent_loop()`，ReAct Turn、上下文、消息保存与工具编排统一收入 `Agent`，子 Agent 也复用同一对象。
- 无状态 Agent 事件构造集中到 `events.py`，删除 Agent 内部的单行消息保存转发方法，主文件只保留 ReAct 编排。
- 参照 pi-agent 将公开事件收敛为 `AgentEvent` 生命周期判别联合，明确 Run/Turn/Message/Tool/Approval 语义。
- Provider 增量收入 `message_update.assistant_event`，整个 Run 使用单调 `sequence`，对外坐标统一为 `session_id + run_id + turn_id`。

## 设计原则

1. 优先删除转发层，不为“以后可能”提前建立接口；
2. 抽象必须对应多实现、插件扩展或明确测试替换点；
3. LLM 保持对 Agent 无感，Agent 不依赖 Backend 或 CLI；
4. Agent 负责产品级编排，复杂算法放在对应功能模块；
5. 新能力通过 Tool、Hook 或回调扩展，不在主循环增加产品分支；
6. 每个里程碑都以行为测试和文档同步为完成条件。
