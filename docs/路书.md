# Camel Harness 路书

## 当前状态

当前版本已经完成从 DDD/六边形分层到 pi-agent 风格功能模块架构的迁移：

- `AgentLoop`、`Agent`、`Harness` 三层运行核心已经建立；
- 旧 `core/application/domain/infra/adapter/bootstrap` 已删除；
- LLM、Session、Tools、Resources 和 Compaction 按功能就近组织；
- API 与 CLI 直接通过 Harness 使用运行时；
- Tool ABC 保持在 `backend.types`；
- OpenAI/Anthropic、JSONL 会话、SSE、审批、MCP、Skill、Memory、子 Agent 和压缩行为保持可用。

## 已完成里程碑

### M1：核心 Agent Runtime

- 流式多 Step ReAct Loop；
- 规范消息、工具调用和事件；
- Step、token、时间与重复调用保护；
- 完整消息保存点与异常流保护。

### M2：Provider 与会话

- Anthropic 默认 Provider；
- OpenAI 与 Anthropic 官方 SDK Adapter；
- 用户级 `~/.camel/sessions/`；
- `metadata.json`、`messages.jsonl` 和 `context.jsonl`；
- 会话 CRUD、工作区过滤和恢复。

### M3：工具与安全

- Tool ABC 与直接字段式定义；
- 文件、Shell、搜索、Skill、Memory 和子 Agent 工具；
- 参数校验、权限模式、审批、超时和大结果落盘；
- Entry Point 插件与 MCP。

### M4：上下文与界面

- 项目规则、Skill、Memory 动态上下文；
- 追加式上下文投影与历史压缩；
- CLI、FastAPI SSE 和 React WebUI；
- thinking 流展示和会话工作区界面。

### M5：架构简化

- 删除五领域 DDD 结构和 ApplicationService 转发层；
- 将 ReactAgent 拆为 AgentLoop、Agent 和 Harness；
- 合并领域契约与技术实现到对应功能模块；
- 单一 `runtime.py` 取代多份 wiring；
- 架构守卫改为验证运行边界，而不是验证目录仪式。

## 下一阶段

- 增加 steering 和 follow-up 消息队列；
- 明确 idle、turn、compaction、retry 阶段；
- 增加主动取消、重试和恢复 API；

- MCP 连接状态和重连策略；
- 工具耗时、Provider usage 和错误指标；
- 插件隔离、版本约束与健康报告；

### P5：发布准备

- OpenAI 与 Anthropic 真实 API 冒烟；
- macOS/Linux CLI 与 Web 启动验证；
- 打包、版本策略和变更日志；
- 安全审查和端到端回归测试。

## 设计原则

1. 优先删除转发层，不为“以后可能”提前建立接口；
2. 抽象必须对应多实现、插件扩展或明确测试替换点；
3. Agent Loop 保持与持久化和 UI 无关；
4. Harness 负责产品级编排，但复杂算法继续放在独立功能模块；
5. 新能力通过 Tool、Hook 或回调扩展，不在主循环增加产品分支；
6. 每个里程碑都以行为测试和文档同步为完成条件。
