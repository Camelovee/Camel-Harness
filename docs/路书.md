# 路书

定位：面向本地编码任务的轻量 Agent Runtime，优先证明任务效果与可靠性，不建设通用多租户平台。

## 当前状态

- 已实现流式 ReAct、Anthropic/OpenAI、权限审批、核心文件/Shell 工具、MCP、子 Agent、Skill、Memory、上下文压缩和取消恢复。
- CLI 与 WebUI 共用 Harness；Session 使用本地 JSONL 历史树，配置使用用户级 JSON。
- Agent 直接构造生命周期事件，统一完整消息保存点；工具阶段返回结果集合，恢复计划与 Run 登记在同一启动锁内完成，不新增编排层。
- 已修正 MCP 连接任务归属、归档故障终止边界与工作区外结果引用读取；子 Agent 组合集中在 runtime，引用按会话与当前分支隔离。
- 已补齐上下文超限恢复：规范错误分类、首事件前强制压缩、同 Turn 重发，每 Run 最多一次；失败摘要不提交，不重复保存用户输入或执行历史工具，取消和运行限制继续生效。
- 已实现项目/用户双层记忆：同名项目优先、预算内中英文检索、按需分页读取及始终审批的显式修改；文件锁保护版本提交，子 Agent 仅只读，不自动提取会话。
- 已补齐 Windows 文件锁、安全文件打开、目录同步差异、Shell 进程树清理和目录选择器；新增 Windows 专项 CI，原生验收结果待实际运行确认。
- 已公开到 [GitHub](https://github.com/Camelovee/Camel-Harness)，采用 MIT；提交 `c6facd2` 的远端 CI 已通过。
- README 已包含实际 WebUI 默认模型设置截图，截图使用隔离临时数据；包含私人目录或会话的截图不纳入公开仓库。
- 本地最近验证：macOS 上 412 项 Python 测试、15 项前端测试、11/11 离线协议任务及 6/6 记忆开关对照通过，Mypy 同时按默认与 win32 平台检查；Windows 原生 CI 待运行，记忆对照为假模型协议验证。
- 真实效果证据仍是旧版本单次 6/10，见 [评测说明](../evals/README.md)；不能代表当前版本或稳定成功率。

## P0：可复现交付

- 持续验证干净安装与远端 CI，保持启动步骤可复现。
- 确认 Windows 专项 CI 与原生双终端启动、目录选择、中文输出和取消回收；不以模拟分支测试代替原生运行证据。
- 补三分钟真实演示，展示工具执行、审批、取消与恢复。
- 补 OpenAI 真实文本、工具调用和取消烟测，记录模型、配置与日期。

验收：他人按 README 可启动并复现演示；无密钥时测试正常，安全限制明确。

## P1：效果与可靠性

- 优先重复运行现有真实任务，再扩展到 20–30 个仓库任务；每项至少三次，记录成功率、Turn、token、延迟和失败原因。
- 使用工作区最终状态与测试判分，减少精确文本匹配误判；对 Skill 和压缩做受控对比。
- 增加长文件、压缩后约束保留、断流、重启与恢复专项评测；用真实失败样本验证已实现的有界上下文溢出恢复及摘要质量。
- 基于现有运行坐标补脱敏诊断摘要，记录工具/审批耗时、重试、压缩和错误来源。
- 记忆首版 [设计与验收](方案设计/记忆系统设计.md) 已落地；离线启用/禁用对照只验证上下文协议。真实任务仍需评测检索质量、错误引用、约束保留及 token 开销，再决定是否扩展检索策略。
- 已完成 100/1,000/10,000 条消息的 [Session 重放基准](会话性能基准.md)，暂不引入缓存；出现实际瓶颈后先补多会话和大消息测量，再评估增量投影。

验收：有可复现的改动前后对比、失败轨迹和修复案例，能解释效果与成本，而不只报告测试数量。真实模型调用另行授权，不自动进入普通测试。

## P2：按瓶颈扩展

- 有评测收益再增加只读工具并行、必要 Hooks 或 MCP 重连，不为了功能数量增加抽象。
- 若执行不可信代码或开放远程服务，先补威胁模型、提示注入测试与受限执行环境。
- 分支导航、动态模型切换等入口能力按实际使用需求完善。

暂不优先：插件市场、多用户、后台 Run 调度器、复杂多 Agent 网络和进一步机械拆包。
